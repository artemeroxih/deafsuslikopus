# DeafSuslik

Дизайн премиального стримингового сервиса, где субтитры — не опция, а продукт.
Веб, iPhone, Android и приватная админ-панель на одной дизайн-системе.

**121 экрана · одна подписка ВИП, 500 ₽ / месяц**

Прототипы открываются по прямой ссылке на экран: `mobile.html#onb3`,
`web.html#cc-settings`, `admin.html#editor`. На этом держится карта пути —
она ведёт не «в прототип», а точно в тот шаг, о котором говорит.

## Ключевые решения

**Имя делится там же, где делится смысл.** `Deaf` — белый, `Suslik` — бирюзовый `#35E0CB`.
Логотип читается как два слова и задаёт всю палитру.

**Два акцента, разделённых по смыслу.** Синий градиент `#2F62F5 → #5842EC →
#46B6F5` — кнопки и всё, что запускает и продаёт.
Ярко-жёлтый `#FFD426` — только субтитры, CC, CC+, доступность и фокус.
Сами субтитры по умолчанию `#FFE81F` — вещательный жёлтый, 16.8:1 поверх
тёмного кадра. Кроме сплошных цветов зритель может выбрать градиентные
заливки «Золото» и «Бриллиант». Тёплый акцент на холодном фоне: текст виден первым, а назначение
кнопки понятно до того, как прочитан её текст.

**Антиква для заголовков, гротеск для субтитров.** Playfair Display даёт
названиям фильмов киношную интонацию. Субтитры остаются в Onest: тонкие штрихи
антиквы разрушаются поверх движущегося кадра, а читаемость реплики здесь важнее
красоты строки.

**CC+ как продукт, а не настройка.** Бейдж на карточках, кнопка первого уровня
в плеере, отдельный фильтр, отдельный раздел профиля, живой редактор внешнего
вида. От плеера до нужного языка — одно касание.

**Онбординг стоит до регистрации.** Четыре экрана при первом запуске объясняют,
зачем заводить аккаунт, а не поздравляют с уже заведённым: каталог, CC+, офлайн,
синхронизация. На каждом шаге есть «Пропустить» — онбординг объясняет, но не
задерживает.

**Замкнутая петля поддержки.** Кнопка «Проблема?» прикладывает фильм, тайм-код и
номер реплики. Обращение уходит редактору субтитров, тот открывает ровно этот
момент в редакторе, публикует правку — зрителю приходит «исправлено».

## Сборка

Каждая страница собирается из общего слоя токенов и компонентов — консистентность
не на глаз, а по построению.

```bash
python3 build.py          # собрать всё
python3 build.py web      # собрать одну страницу
```

Сборка выдаёт два варианта из одних исходников:

- `./<name>.html` — самостоятельная страница; её отдают GitHub и Vercel
- `./artifacts/<name>.html` — только тело; его оборачивает хост Claude Artifacts

Перед сборкой каждый JS проверяется через `node --check`: страница со сломанным
скриптом не должна выглядеть просто «пустоватой».

### Структура

```
src/
  tokens.css        цвет, типографика, отступы, радиусы, тени, движение
  components.css    компоненты — 1:1 к будущим React-компонентам
  core.js           логотип, иконки, генератор обложек, каталог, подписка
  web-*.js          экраны веба
  mobile-*.js       экраны iOS и Android
  admin-*.js        экраны админ-панели
  flow.body.html    карта пути; список экранов в неё генерирует build.py
  *.body.html       разметка и роутер каждой страницы
build.py            сборка
```

## Деплой

Статика без шага сборки — ни Node, ни установки зависимостей.

**GitHub Pages** отдаёт `main` из корня; `.nojekyll` не даёт Jekyll трогать файлы.
Это основной адрес.

**Vercel** (`vercel.json`) настроен на те же файлы: Framework Preset — **Other**,
Build Command и Output Directory пустые.

`all.html` собирает шесть страниц в один файл: одна ссылка вместо шести, работает
и как локальный файл, и как артефакт. Внутренние ссылки вида `web.html#player`
там ведут на нужную вкладку, а адрес пишется как `#mobile/onb2`.

Страницы отдаются с `X-Robots-Tag: noindex` — прототип не попадёт в поисковую
выдачу.

## Материалы

Обложки фильмов генерируются процедурно из названия — детерминированные
градиенты вместо чужих постеров. Каталог юридически чист и визуально однороден.

Логотип нарисован с нуля: скруглённый токен, внутри вырезан силуэт суслика,
в груди — треугольник Play. Читается на 16 px. Слово набрано Onest ExtraBold,
а не антиквой — на 15–16 px её волосяные штрихи на тёмном фоне пропадают.
